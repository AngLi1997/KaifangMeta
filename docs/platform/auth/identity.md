# 统一认证与身份

> 平台 · 认证模块。相关：[网关与鉴权](../../gateway.md)（Token 设计、轻租户）、[应用接入](app-onboarding.md)、[统一权限组件](authz.md)。

## 要点

- **身份账号集中维护**：平台或现有统一身份源负责登录账号、认证凭据、全局唯一且不复用的用户 ID（`sub`）、账号启停与登录 / SSO（OIDC）。已有企业 IdP / LDAP 时优先复用，由平台联邦接入，不再复制一份身份主数据。
- **业务用户信息由业务系统维护**：各系统用 `sub` 关联本地用户，维护本系统的用户资料副本、角色、菜单、数据权限与业务状态；不得用姓名或手机号作为用户关联主键。
- **机构由平台维护**：认证模块按租户维护机构树，身份账号归属一个机构；业务系统经身份目录 API 读取机构与账号所属机构，用于选人与数据范围，不另建机构主数据。Token 只传全局身份与必要的租户上下文，不传机构、角色、菜单或权限。
- 控制台成员与身份账号是两类数据：成员表示 `sub` 已开通控制台应用，身份账号表示可登录的平台身份；二者只按 `sub` 关联。
- 控制台提供「身份账号」和「租户管理」页面。身份账号可手动新建、编辑、停用，停用后可删除；租户可新建、改名和停用，只有已停用且无账号、成员与其他应用引用的空租户可删除，避免破坏引用。
- 新建身份账号默认不创建控制台成员；控制台成员仍按 `sub` 独立关联，IAM 账号启用不代表已开通控制台。
- **轻租户**：租户信息由平台「租户管理」维护，身份账号归属一个主租户，可经成员关系加入其他租户（登录时选择，一个 Token 只含一个 `tid`）；平台超级管理员属于系统租户 `t_system`；租户是中台数据与配置的隔离边界，机构树在租户之内，见下文「机构」。Token 按需带 `tid`，应用按租户开通。停用租户会阻止新登录并由网关拒绝该租户尚未过期的 Token。高隔离要求的单位采用独立部署。详见 [网关与鉴权](../../gateway.md)。

## 身份账号、控制台成员与业务用户

- **身份主数据**由平台 IAM 或接入的企业 IdP / LDAP 维护：登录账号、认证凭据、全局唯一 `sub`、账号启停与 SSO。已有统一身份源时优先复用，由平台联邦接入，不另建一套用户主数据。
- **控制台成员**存于 `console_authz.user`，是 `kaifang-meta-console` 的本地应用成员记录，保存控制台资料、按租户的角色绑定（`console_authz.role_binding`：成员 × 角色 × 租户）和最近访问时间，不保存认证凭据。首次在「身份账号」页授予控制台角色时开通成员。
- **身份账号**存于 `iam.account`，保存 `sub`、租户、登录名、邮箱、凭据和账号状态。控制台「身份账号」页展示 IAM 身份字段及其对应的控制台成员信息；两个来源仍是独立数据，不复制凭据或角色。`sub` 由 IAM 生成且只读，创建时必须指定启用的主租户；账号编辑支持改名、邮箱、主租户、其他租户、密码和状态。
- **跨租户成员**存于 `iam.tenant_member`（`sub` × `tenant_id`），用于运维、上级督导等需要进入多个租户的人员；只能由系统租户管理，系统租户不作为成员租户。加入租户时向该租户写 `user.created`；移出租户或转移主租户时吊销该账号的全部会话。
- **租户**存于 `iam.tenant`，由平台控制台管理员创建和维护名称、状态。租户 ID 由 IAM 生成且不可修改；租户停用后，账号不能登录，网关拒绝该租户尚未过期的用户与服务 Token；重新启用后，尚未过期的旧 Token 会恢复可用。删除租户只在系统租户可用：系统租户不能删除；租户须已停用，且没有主租户账号、跨租户成员，也没有内置控制台以外的接入应用开通；删除时从控制台的开通租户中移除、清理该租户的控制台角色绑定并重新下发控制台路由，租户吊销键保留到自然过期。
- 系统租户 `t_system` 是唯一的初始化租户（默认租户），由迁移创建，不能停用；初始化数据只有系统租户与 `CONSOLE_ADMIN_USERNAME` 管理员账号，业务单位的租户与账号在控制台按需新建。新建租户时内置控制台随之开通（租户管理员需要登录控制台）并重新下发控制台路由；其他应用仍需在接入配置中把租户加入 `tenants` 列表。
- `console_authz.user.sub` 与 `iam.account.sub` 只做逻辑关联，不设跨 schema 外键。不得用用户名或邮箱关联，也不得把控制台角色复制进 IAM。
- 合并页面按 `sub` 关联两个来源；IAM 身份是主列表，控制台成员字段作为补充信息。未开通控制台的 IAM 身份仍显示，成员字段标记为“未开通”：

  | 页面 | 数据来源 | 展示内容 | 当前筛选 |
  |------|----------|----------|----------|
  | 身份账号 | IAM `iam.account` + 控制台 `console_authz.user` 及角色关系 | IAM：`sub`、`tenant_id`、登录名、邮箱、账号状态、创建时间；控制台：角色、超级管理员标记、本地启用状态、最近访问时间 | 系统租户展示全部账号；业务租户只展示主租户或成员租户为本租户的账号 |

- **业务用户资料**由各业务系统维护：本系统的用户档案副本、角色、菜单、数据权限与业务状态；所属机构以平台为准。角色与菜单可使用[统一权限组件](authz.md)。业务表以 `sub` 关联本地用户；不得通过姓名或手机号做稳定关联。
- 平台身份目录 API 提供身份账号基础字段（含所属机构 `org_id`）与当前租户机构列表，不提供角色或权限。创建身份账号写入 `user.created` outbox，修改资料（含换机构）写入 `user.updated`，启停写入 `user.enabled` / `user.disabled`，删除向主租户和各成员租户写入 `user.deleted`；机构增删改写入 `org.changed`；事件不包含密码。
- 用户被禁用时，身份源吊销其会话并发送 `user.disabled`；业务系统据此禁用本地映射、清理本地授权并按自身策略撤销会话。
- 业务系统可在本地保存所需的用户资料副本；这些字段由业务系统负责更新，不以平台身份目录为业务主数据来源。

## 机构

- 存于 `iam.org`：`id`（bigint）、`tenant_id`、`parent_id`、`code`（租户内唯一）、`name`、`sort_order`、`status`；层级按 `parent_id` 计算。身份账号 `iam.account.org_id` 指向主租户内的一个机构，可空。
- 控制台「机构管理」维护机构树：新增、编辑、改上级（不能移到自身或后代下）、启停、删除（仅已停用、无下级、无账号）、JSON 导入（保留 `id`，用于从存量系统迁入，已有业务数据中的机构 ID 与编码继续有效）。租户管理员只维护本租户机构。
- 首次底座机构快照由 Alembic `0023` 导入 `t_system`：排除默认演示机构，并把 22 组同名、同编码的父子节点合并为父节点，子节点 ID 到保留 ID 的映射见 [`0023_organization_seed.json`](../../../alembic/versions/0023_organization_seed.json)。业务系统引用被合并 ID 时须先按该映射转换；其他机构 ID 与编码保留。
- 停用机构不影响账号登录，只在选择器中隐藏。
- 身份目录 `GET /kaifang-meta/platform/iam/v1/orgs` 返回当前租户机构平铺列表（含 `level`）；业务按 `id` 或 `code` 引用机构，数据范围、业务角色仍由业务解释。
- 首个接入方案见 [统建系统接入](onboarding-unified-build.md)。迁移 `0021` 落地 `iam.org`、`iam.account.org_id`、「机构管理」菜单与接口；`0023` 导入并规范化底座机构快照；机构变更写入 outbox，业务订阅后续接入。

## 当前运行策略

- `CONSOLE_ADMIN_USERNAME` 仅用于初始化首个控制台管理员；`0003` 创建该 IAM 身份和控制台成员，`0006` / `0010` 清理历史非管理员控制台成员，`0009` 移除旧部门菜单，`0011` 合并身份账号入口，`0012` 增加租户管理菜单和接口权限，`0013` 落地租户级隔离（系统租户、成员租户、角色范围与绑定、审计租户、运行时数据库账号与 RLS）。启动时不再停用非 admin IAM 账号。
- 身份账号停用时保留账号和 `sub`，在同一事务写入 `user.disabled` outbox，再吊销该账号的 SSO、Refresh Token 和网关会话。重新启用写入 `user.enabled`；收到事件的控制台只更新已有成员，不自动创建控制台成员。
- 只有已停用、且不是控制台超级管理员的账号可删除，权限同编辑（租户管理员只能删除主租户为本租户的账号）。删除物理移除 `iam.account` 与其 `iam.tenant_member`，同一事务写入 `user.deleted`，控制台同时删除该 `sub` 的成员及角色绑定；`sub` 不复用，业务系统收到 `user.deleted` 后按自身策略处理本地映射。
- 「身份账号」列表按 `sub` 合并 IAM 账号与控制台成员数据；新账号只在 IAM 中创建，未开通控制台时显示“未开通”。密码由管理员在创建时设置，也可编辑时重置；密码仅存哈希，审计请求会脱敏。
- 菜单和 API 权限按 Token 租户内绑定的角色计算，数据按 Token 的 `tid` 过滤，见[统一权限组件](authz.md)「当前仓库实现边界」。租户管理（新建、修改）只在系统租户可用；租户管理员只管理本租户的账号与控制台角色，不能转移租户、调整跨租户成员或授予租户管理员。
