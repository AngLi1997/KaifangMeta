# 能力点：能力调用配置

> 平台 · 能力模块。相关：[能力目录](catalog.md)、[算子](operator.md)。

## 要点

业务系统经 SDK 按**能力点**调用：`capability("archive.import.ocr").invoke(...)`。代码只声明能力点与契约（算子主版本），具体算子版本、参数、灰度、备用算子、配额在平台中配置并可回滚；调用结果带解析出的算子版本，便于追溯。


## 结论：代码里写“用什么能力”，平台里配“用哪个实现、怎么用”

全部写死会让每次换模型版本、调阈值都要发版；全部可配置（在 UI 上拼业务流程）会让业务逻辑脱离代码，无法测试和评审。因此按**变化频率与影响面**划分：

| 写在代码里（随业务发版） | 在平台中配置（运行时生效，可灰度、可回滚） |
|-------------------------|------------------------------------------|
| 业务在哪些位置使用能力（**能力点**） | 能力点绑定到哪个算子 / 流水线、哪个版本 |
| 能力的**输入输出契约**（算子主版本） | 次版本 / 修订版本、灰度比例 |
| 业务流程本身（如何处理结果、何时送标注） | 参数：DPI、语种、模型温度、置信度阈值 |
| 失败时的业务降级策略 | 超时、重试、备用算子、配额 |

## 能力点（Capability Binding）

业务代码不直接写算子名，而是写**能力点**，形如 `<app>.<场景>`：

```java
// 业务代码：只声明“档案导入需要 OCR”
OcrResult r = km.capability("archive.import.ocr").invoke(input, OcrResult.class);
```

```python
r = km.capability("archive.import.extract").invoke({"text": text, "schema": "ws-item"})
```

能力点在平台配置中解析为具体实现：

```yaml
binding: archive.import.ocr
contract: ocr.general@2          # 主版本 = 契约，改主版本必须改代码
target:
  operator: ocr.general
  version: 2.3.0                 # 或别名 stable / canary
  canary: { version: 2.4.0-rc1, percent: 10 }
params: { dpi: 300, lang: zh }
policy: { timeout: 30s, retries: 2, fallback: ocr.lite@1.4.0 }
quota: { qps: 20, daily: 200000 }
```

- `contract` 由能力点创建时确定。平台**拒绝**把能力点绑定到不兼容主版本的算子（按算子 `/meta` 中的 JSON Schema 校验）。
- 绑定目标可以是单个算子，也可以是**流水线**（如 `pipeline.archive-parse@3`：文本层检测 → `pdf.text` / OCR → `extract.doc`）。流水线是平台中定义、带版本的配置，由平台 Worker 执行（见 [任务调度](../scheduler.md)）。模型、知识库、Agent 同样可以作为绑定目标，见 [能力目录](catalog.md)。
- 允许直接调用 `invoke("ocr.general@2.3", …)`，仅用于原型验证和脚本；控制台会把“未使用能力点的调用”列为待治理项。

## 配置的作用域与生效

- 解析顺序：**租户 × 应用 × 能力点** > **应用 × 能力点** > 能力点默认值。大部分情况只需配置后两层。
- 配置同样走 **草稿 → 发布** 流程，每次发布生成不可变的绑定版本号，可一键回滚到任一历史版本；发布前可在控制台用样例数据试跑。
- SDK 本地缓存解析结果（TTL 60 秒），并订阅 `capability.binding.changed` 事件主动失效。真正的调用由能力模块路由，所以 SDK 缓存只影响参数预校验，不会导致调用到旧版本。
- **可追溯**：每次调用的返回结果中带 `resolved: { binding_version, operator, version, params_hash }`。业务系统需要把它和结果一起保存（如著录项来源），满足档案场景“这个字段是哪个模型版本识别的”的审计要求。

## 业务侧阈值放哪里

如“置信度低于 0.85 送标注”这类**业务规则阈值**：属于业务配置，放在业务系统自己的配置中心 / 系统参数表（智慧档案室的“导入规则”），**不放能力平台**——能力平台只负责算子本身的参数。原则：参数影响的是“算子怎么算”放平台，影响“业务怎么处理结果”放业务。
