# 能力目录与能力下放

> 平台 · 能力模块（控制面）。相关：[能力点](binding.md)、[算子](operator.md)、[知识库与 Agent 版本](knowledge-agent.md)、[AI 模块运行时](../ai/overview.md)、[WeKnora 知识库引擎](weknora.md)。

## 要点

- 能力是一个**目录**，单个算子只是其中一类：算子、流水线、模型、知识库、Agent 都登记为能力，统一授权、绑定、计量和调用。
- 能力模块是控制面（目录、授权、能力点绑定、调用路由、配额计量、审计）；算子节点、AI 模块、任务调度模块是提供方，各自管理资源生命周期，发布版本时向目录登记。AI 模块通过运行时适配器执行 Agent，首版适配 DeepSeek Harness。
- 可见性分公共 / 受限 / 私有三级。每个应用自动拥有**应用空间**，由应用管理员自助管理能力点绑定、私有知识库、Agent、流水线；能力经“授权 → 配置 → 自建资源 → 交付”四层下放给业务系统。
- 知识库等含业务数据的能力：入库带 ACL 元数据，业务后端按用户权限传入过滤条件，可声明强制过滤字段。


## 能力是一个目录，算子只是其中一类

**结论：对业务系统暴露的是统一的能力目录。** 目录中的每一项是一个“能力”，单个算子只是其中一种类型；模型、知识库、Agent、流水线同样是能力，用同一套方式登记、授权、绑定、计量和调用。

| 类型 | 示例 | 提供方（实现所在） | 调用接口 | 版本语义 |
|------|------|-------------------|---------|---------|
| 算子 `operator` | `ocr.general`、`extract.doc` | kaifang-meta-operator 节点 | `invoke` 同步 / 异步 | 语义化版本，主版本 = 契约 |
| 流水线 `pipeline` | `pipeline.archive-parse` | 任务调度模块（PostgreSQL 任务表 + Worker） | 异步 `run` + 回调 | 语义化版本 |
| 模型 `model` | `llm.chat`、`llm.chat.lite`、`embed.text` | AI 模块 · 模型网关 | OpenAI 兼容 chat / embeddings，支持流式 | 模型标识固定；模型网关别名 + 主版本，如 `llm.chat@1` |
| 知识库 `kb` | `kb.archive-spec` | AI 模块 | `retrieve` 检索；文档增删 | 不可变快照 vN + `prod` 别名 |
| Agent `agent` | `agent.archive-qa` | AI 模块 | 会话 `chat`，流式，工具调用 | 不可变快照 vN + `prod` 别名 |

**模块分工：能力模块是控制面，其他模块是提供方。**

- **能力模块**负责所有类型共有的部分：目录、可见性与授权、能力点绑定、统一调用入口与路由、配额计量、审计。
- **提供方**负责各自资源的生命周期：
  - 算子节点：运行算子；
  - AI 模块：接入模型、管理提示词 / Skills / MCP / 知识库 / Agent，编译运行计划并通过运行时适配器执行；
  - AI Runtime：独立执行进程，首版运行 DeepSeek Harness；后续可接 Pi Agent 或 WeKnora Agent；
  - 任务调度模块：执行流水线。
  
  提供方发布新版本时，通过接口向目录登记。
- 因此知识库、Agent 不需要搬进能力模块，模块之间仍然只走接口；平台控制台的“能力”分组以目录为入口，知识库、Agent、模型页面是对应类型的管理页。

每个目录项有以下公共字段：标识与名称、类型、归属（平台或某个应用空间）、可见性、版本与别名、契约（输入输出 Schema 或接口类型）、资源与 SLA、默认配额、提供方地址。

**依赖关系**：Agent 依赖模型、提示词、Skills、MCP 工具和知识库；知识库依赖向量模型。发布版本时锁定依赖并记录依赖图；目录中展示“被谁依赖”，能力下线或回滚前先检查依赖方。

## 能力的归属：平台公共能力 + 应用空间

**可见性分三级**：

| 可见性 | 含义 | 典型能力 |
|--------|------|---------|
| 公共 `public` | 所有应用可用，开通即授予默认配额 | `pdf.text`、`image.deskew`、`embed.text` |
| 受限 `restricted` | 需能力负责人审批，审批时确定配额 | 大模型、GPU 消耗大的算子、跨应用共享的知识库 |
| 私有 `private` | 只属于某个应用空间 | 某业务系统自建的知识库、Agent、流水线 |

**应用空间（Space）**：每个接入的应用自动拥有一个空间 `space.<app>`，这是“下放”的载体。

- 空间内的资源由**应用管理员**自助管理，平台团队不参与日常配置。应用管理员是平台控制台的内置角色（作用范围为本应用空间，见 [统一权限组件](../auth/authz.md)），在应用接入时指定，只能看到本空间和公共目录。
- 空间内可以管理：
  - 能力点绑定
  - 私有知识库与知识库文档
  - Agent、提示词、Skills 与 MCP 工具
  - 流水线
  - 私有算子：按同一算子协议注册；镜像由业务方提供，可由平台托管运行，也可由业务方自行部署后登记地址
- 空间内的资源只能引用**已授权**给本应用的能力。例如 Agent 只能选用本应用已获批的模型。
- **提升为公共**：私有能力被多个应用需要时，经评审转为公共能力，所有权移交平台团队，原空间的能力点绑定自动指向公共版本。

**与租户的关系**：

- **定义**在应用的所有开通租户间共享，包括 Agent、流水线、能力点、知识库的切片与检索配置。
- **数据**按租户隔离，包括知识库文档与索引、会话、调用记录。
- 同一个知识库定义在每个租户下有各自的文档集和索引版本。

## 下放的四个层次

| 层次 | 下放给业务系统的是什么 | 方式 |
|------|----------------------|------|
| **授权** | 能用哪些能力 | 应用空间发起申请 → 能力负责人审批 → 以“应用 × 租户”授予，带配额（对应应用接入的“平台权限”） |
| **配置** | 怎么用 | 应用管理员自助配置能力点绑定、参数、灰度，范围受授权约束；草稿 → 发布 → 可回滚 |
| **资源** | 自建知识库、Agent、流水线 | 在应用空间内自助创建，引用已授权的模型和算子 |
| **交付** | 如何到达最终用户 | SDK / API、前端组件、MCP 工具，见下 |

交付方式：

- **后端调用**：`km.capability("<能力点>")` 按绑定目标的类型返回对应客户端：`OperatorClient`、`PipelineClient`、`ModelClient`、`KbClient` 或 `AgentClient`。业务代码只依赖能力点，不依赖类型背后的提供方。
- **数据入库**：
  - 推送：业务系统调用知识库文档接口，以 `external_id` 做 upsert / delete，平台增量构建索引。例如智慧档案室在档案著录确认后推送全文。
  - 拉取：配置数据采集模块的连接器定时拉取，适合不便改代码的系统。
- **前端组件**：`kaifang-meta-shell` 提供可嵌入组件，如问答面板、检索框、字段差异对比。组件经**业务后端代理**调用平台，浏览器端不持有服务 Token，业务后端在代理时注入用户过滤条件（见上文“最终用户的权限与数据范围”）。
- **桌面端**：[Agent 桌面端](../../harness.md) 的 Agent 在本机运行，以 `space.harness` 获得模型、知识库授权，用用户 Token 直接调用模型，知识库经平台知识库 MCP 检索（后续）；因无业务后端计算过滤条件，只能使用未声明强制过滤字段的知识库。
- **Agent 工具**：业务系统登记工具名称、用途与 JSON Schema；平台按 MCP 工具契约暴露给 Agent。工具执行留在发起会话的业务后端，由其按当前用户权限执行并回传结果，平台不主动调用业务接口。

## 最终用户的权限与数据范围

平台只识别“哪个应用、哪个租户、代表哪个用户”，不理解业务权限（权限在业务系统）。知识库、Agent 这类携带业务数据的能力，按以下方式保证用户只看到有权看的内容：

- **入库带 ACL 元数据**：文档入库时附带全宗号、密级、组织、可见范围等字段，字段由知识库定义声明；组织值由业务系统提供，不来自平台组织目录。
- **调用时由业务传过滤条件**：业务后端根据当前用户的业务权限计算过滤条件，并随检索或 Agent 调用一起传入。知识库可声明**强制过滤字段**，调用缺少这些字段时直接拒绝，避免漏传导致越权。
- **代表用户调用**：Agent 会话以代表用户的方式调用（模式 B 用 Token Exchange，模式 A 用 `X-KM-On-Behalf-Of`，见 [鉴权流程](../../auth-flow.md)），审计记录落到具体用户。
- **按密级路由模型**：密级高于阈值的内容不送外部模型，由模型网关按数据密级路由到本地部署的模型。

## 计量与配额

- **计量维度**：能力 × 版本 × 应用 × 租户 × 日。不同类型的计量单位不同：
  - 模型：按 token；
  - 算子：按次或按页；
  - GPU 型算子：可按 GPU 秒。
- **配额分三层**：
  1. 能力的全局容量
  2. 应用 × 租户配额
  3. 能力点限流
  
  超额时可选三种策略：拒绝、排队、降级到备用能力。
- 应用空间首页展示用量与成本，月度报表可用于内部结算。

## 与[能力点](binding.md)的关系

能力点的绑定目标可以是**任何类型**的能力，契约检查按类型进行：

| 绑定目标类型 | 检查内容 |
|-------------|---------|
| 算子 / 流水线 | 主版本输入输出 Schema |
| 模型 | 接口类型（chat / embedding）与上下文长度 |
| 知识库 | 检索接口与强制过滤字段 |
| Agent | 输入输出 Schema 与工具清单 |

例如能力点 `archive.qa.agent` 可以从 `agent.archive-qa@prod` 切到新版本，也可以在评测通过后改绑到另一个 Agent，业务代码不变。
