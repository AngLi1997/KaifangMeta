# KaifangMeta 开发规范

## 开始前

- 先读改动涉及的实现，追踪入口、调用方、配置、数据迁移和实际副作用；修 bug 时查清根因及所有调用方，再在共享位置修复。
- 保持现有模块边界、接口和项目惯例。需要改动的范围由用户目标决定，不顺手扩展功能或引入不必要的抽象。
- 发现实现与架构文档、原型或其他文档不一致时，按 [kaifang-meta-docs](../kaifang-meta-docs/SKILL.md) 处理；涉及前端页面或交互时，按 [kaifang-meta-ui](../kaifang-meta-ui/SKILL.md) 处理。

## 完成后验证

- 功能开发或 bug 修复完成后，必须从真实入口走通受影响的端到端完整流程，并检查关键结果及副作用，例如响应、界面状态和持久化数据。验证范围覆盖改动实际影响的用户路径。
- 不能用单元测试或局部 mock 代替端到端流程，也不要为单元测试编写临时 `test` 脚本。可以使用已有项目工具和测试设施辅助验证，但不能据此声称端到端流程已通过。
- 若确有特殊情况必须用临时 `test` 脚本辅助验证，完成后立即删除，不把脚本留在仓库。
- 若环境或依赖阻止完整流程运行，明确报告未覆盖的步骤和具体阻塞；不得把未执行描述为通过。
